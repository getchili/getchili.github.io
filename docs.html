Guide de Chili

Tu écris ton programme sur ton PC, tu l'envoies à ton ESP32 en une commande, par USB ou WiFi, et il tourne. Pas besoin de reflasher la carte à chaque modification.

Il te faut un PC sous Windows 10 ou 11, une carte ESP32 classique (type « ESP32 DevKit ») et un câble USB de données.

chili check-port                # détecte la carte
chili flash                     # installe le firmware Chili (une seule fois)
chili push examples\blink.chl   # envoie et lance un programme

Tu préfères la souris ? Installe Chili Lab, l'application de bureau : détection de la carte, envoi des programmes, console et firmware, avec des boutons.

Étape 1

Installation

Un seul fichier, sans droits administrateur. Il contient le compilateur, le firmware de la carte et les exemples.

  1. Télécharge ChiliSetup-x.y.z.exe (par exemple ChiliSetup-0.1.0.exe) sur la page des versions.
  2. Double-clique dessus.
  3. Si Windows affiche « Windows a protégé votre ordinateur » (SmartScreen) : clique sur Informations complémentaires, puis Exécuter quand même. Ce message apparaît pour tout programme récent non signé ; il ne signale pas un virus.
  4. Laisse les options cochées, surtout Ajouter chili au PATH (c'est ce qui permet de taper chili dans un terminal). L'extension VS Code n'est proposée que si VS Code est installé.
  5. Clique sur Installer, puis Terminer.

Chili est installé dans %LOCALAPPDATA%\Programs\Chili : bin\chili.exe et les exemples dans examples\.

Vérifier

  1. Ouvre un nouveau terminal : menu Démarrer → tape PowerShell → Entrée. Un terminal ouvert avant l'installation ne connaît pas encore la commande.
  2. Tape :
chili version
chili 0.1.0 (firmware ESP32 embarqué : 0.2.0, bytecode v2)

Si tu vois chili : Le terme «chili» n'est pas reconnu…, ouvre un nouveau terminal. Sinon, relance l'installateur avec Ajouter chili au PATH coché.

Mettre à jour, désinstaller

  • Mise à jour : lance l'installateur de la nouvelle version, puis chili flash pour mettre à jour le firmware de la carte.
  • Désinstallation : Paramètres Windows → Applications → Applications installées → Chili → Désinstaller.
Étape 2

Premiers pas : faire clignoter la LED

Brancher l'ESP32, y installer le firmware Chili, puis envoyer un programme qui fait clignoter sa LED bleue. Compte 5 minutes.

Cette partie utilise le terminal. Tout se fait aussi à la souris avec l'application Chili Lab : elle détecte la carte, propose Installer Chili sur la carte, puis Envoyer à côté de blink.chl.

1. Brancher la carte

Branche l'ESP32 avec un câble USB de données. Beaucoup de câbles (écouteurs, batteries) ne font que charger : la carte s'allume mais le PC ne la voit pas. Si rien n'est détecté, change d'abord de câble.

2. Installer le pilote USB (si besoin)

Windows 10/11 l'installe souvent tout seul. Sinon, regarde le nom de la puce écrite près du port USB de la carte :

PucePilote
CH340, CH9102CH341SER (WCH)
CP2102, CP2104 (CP210x)CP210x VCP (Silicon Labs)

Débranche et rebranche la carte après l'installation.

3. Détecter la carte

chili check-port
Ports série :
  COM4     WCH CH340 (1A86:7523)  <- carte ESP32 probable

COM4 :
  Firmware Chili : absent
  Puce           : ESP32  (MAC 08:3a:f2:12:34:56)

  La carte est prête à recevoir le firmware Chili :
    chili flash COM4

Le port (COM4 ici) peut être différent chez toi. Avec une seule carte branchée, chili la trouve seul. Sortie différente ? Voir Dépannage.

4. Installer le firmware Chili

Le firmware est le programme qui reste sur la carte et exécute tes programmes Chili. On l'installe une fois par carte (et après chaque mise à jour de Chili).

chili flash
Installation du firmware Chili 0.2.0 sur COM4.
Ne débranche pas la carte pendant l'opération.

  [##############################] 100 %  firmware.bin

Firmware écrit et vérifié en 28 s. Redémarrage de la carte…
Firmware Chili 0.2.0 opérationnel sur ESP32-D0WD-V3.

Ta carte a déjà un firmware Chili plus ancien que 0.2.0 ? Relance aussi chili flash : les programmes actuels (class Main, function) ne tournent pas dessus.

Si la carte « ne passe pas en mode programmation automatiquement » :

  1. maintiens le bouton BOOT enfoncé ;
  2. appuie une fois sur EN (ou RST) ;
  3. relâche BOOT ;
  4. relance chili flash.

5. Envoyer ton premier programme

Copie d'abord les exemples dans tes Documents pour pouvoir les modifier, puis va dans ce dossier :

Copy-Item "$env:LOCALAPPDATA\Programs\Chili\examples" "$HOME\Documents\chili" -Recurse
cd "$HOME\Documents\chili"
chili push blink.chl
Envoi de blink.chl (188 octets) vers COM4… ok (180 ms)
Programme enregistré sur la carte et lancé. Il redémarrera tout seul à chaque mise sous tension.
Sortie de la carte — Ctrl+C pour quitter (le programme continue de tourner).

La LED bleue clignote. 🎉 Ctrl+C ferme l'affichage, mais le programme continue de tourner. Il est enregistré sur la carte : débranche-la, rebranche-la (même sur un chargeur), il repart tout seul.

Pas de LED sur la broche 2 ? Branche une LED et une résistance de 220 Ω entre GPIO 2 et GND.

Modifier le programme

  1. Ouvre blink.chl dans VS Code ou le Bloc-notes.
  2. Remplace let period = 500 par let period = 100 et enregistre.
  3. Relance chili push blink.chl : la LED clignote plus vite. L'envoi prend moins d'une seconde.

Référence

Le langage

Chili est volontairement petit : des entiers, des variables, des fonctions, des conditions, des boucles et des classes.

Pour tester sans carte :

chili check mon_programme.chl   # vérifie qu'il n'y a pas d'erreur
chili run mon_programme.chl     # l'exécute sur le PC (broches simulées)

Structure d'un programme

Un fichier .chl contient des variables globales, des fonctions et des classes. Il doit avoir une classe Main avec une fonction main() : c'est elle qui est lancée au démarrage.

// blink.chl — fait clignoter la LED de la carte
let led = 2          // variable globale

class Main {
    function main() {
        gpio.mode(led, 1)
        while true {
            gpio.write(led, 1)
            delay(500)
            gpio.write(led, 0)
            delay(500)
        }
    }
}

Au démarrage, la carte initialise les variables globales (dans l'ordre du fichier), crée un objet Main, puis appelle sa fonction main(). Pour l'instant, retiens simplement le modèle : ton programme va dans class Main { function main() { … } }.

  • // commence un commentaire jusqu'à la fin de la ligne.
  • Pas de point-virgule en fin de ligne : Chili les ajoute tout seul. On n'en met que pour deux instructions sur une ligne : gpio.write(2, 1); delay(100).
  • L'indentation est libre (4 espaces est l'usage).

Les anciennes versions écrivaient fn main() { … }. Ce n'est plus accepté : les fonctions s'écrivent function, et main va dans class Main.

La règle d'or : l'accolade sur la même ligne

L'accolade { doit être sur la même ligne que class, function, if, else ou while. Et else se met sur la même ligne que le } qui le précède.

// ✅ correct
if x > 0 {
    print(x)
} else {
    print(0)
}

// ❌ incorrect
if x > 0
{
    print(x)
}
else {
    print(0)
}

Pourquoi : Chili ajoute un point-virgule invisible en fin de ligne quand elle se termine par un nom, un nombre, ) ou }. if x > 0 suivi d'un retour à la ligne devient if x > 0;.

Nombres

Une seule sorte de valeur : l'entier signé 32 bits, de -2 147 483 648 à 2 147 483 647. Pas de nombres à virgule ni de texte pour l'instant. Les objets (voir Classes) se rangent eux aussi dans des variables.

ÉcritureValeurRemarque
4242décimal
0x2A42hexadécimal
0b10101042binaire
1_000_0001000000_ est un séparateur ignoré
true / false1 / 0
  • Débordement : les calculs font le tour, 2147483647 + 1 donne -2147483648.
  • Division entière : 7 / 2 vaut 3, -7 / 2 vaut -3, -7 % 2 vaut -1.
  • Division par zéro : erreur d'exécution, le programme s'arrête (pas la carte).
  • Vrai / faux : 0 est faux, toute autre valeur est vraie. Les comparaisons renvoient 1 ou 0.

Variables

On déclare avec let et une valeur de départ (obligatoire), puis on modifie avec =, +=, -=, *=, /=, %=. Pas de ++ : écris i += 1.

let vitesse = 100
vitesse = 200
vitesse += 10   // vitesse = vitesse + 10
  • Déclarée hors de toute fonction et de toute classe : variable globale, visible partout, initialisée avant main dans l'ordre du fichier.
  • Déclarée dans un bloc { … } : locale à ce bloc.
  • Pas deux let du même nom dans un bloc. Dans un bloc imbriqué, un nouveau let masque l'ancienne variable jusqu'à la fin du bloc.
  • Un let écrit directement dans une classe est un champ de l'objet : voir Classes.
let compte = 0              // globale

function ajoute() {
    compte += 1             // modifie la globale
}

class Main {
    function main() {
        ajoute()
        print(compte)       // 1
        if true {
            let compte = 99 // locale au bloc
            print(compte)   // 99
        }
        print(compte)       // 1
    }
}

Noms : une lettre ou _, puis lettres, chiffres ou _, sans accents (classes avec une majuscule par habitude). Interdits : les mots-clés (function let if else while return break continue true false class abstract extends constructor this super new) et les natives (print, delay, millis, random, gpio).

Du plus prioritaire au moins prioritaire :

&& et || s'arrêtent dès que le résultat est connu (dans b != 0 && a / b > 2, pas de division si b vaut 0) et renvoient 1 ou 0. En cas de doute, mets des parenthèses.

print(1 << 4)            // 16
print(0b1100 & 0b1010)   // 8
print(0b1100 | 0b1010)   // 14
print(5 > 3 && 2 > 1)    // 1

Conditions : if / else

if temperature > 30 {
    gpio.write(ventilo, 1)
} else if temperature < 25 {
    gpio.write(ventilo, 0)
} else {
    // rien à faire
}

Pas besoin de parenthèses autour de la condition (elles sont permises). Les accolades sont obligatoires.

Boucles : while, break, continue

Une seule boucle, while (pas de for). break sort de la boucle, continue passe au tour suivant.

let i = 0
while true {
    i += 1
    if i % 2 == 0 {
        continue     // saute les nombres pairs
    }
    if i > 9 {
        break        // on s'arrête après 9
    }
    print(i)         // 1 3 5 7 9
}

Fonctions

Une fonction se déclare avec function, au niveau global (hors des classes) :

function carre(n) {
    return n * n
}

function fib(n) {
    if n < 2 {
        return n
    }
    return fib(n - 1) + fib(n - 2)
}

class Main {
    function main() {
        print(carre(7))   // 49
        print(fib(10))    // 55
    }
}
  • Zéro, un ou plusieurs paramètres, séparés par des virgules.
  • Une fonction renvoie toujours une valeur : celle du return, ou 0.
  • On peut l'appeler avant sa définition dans le fichier. La récursion est permise.
  • Pas de fonction à l'intérieur d'une autre fonction.
  • Une instruction seule doit être un appel : carre(3) est permis, x + 1 seul ne l'est pas.
  • Une function écrite dans une classe est une méthode, comme main dans class Main : voir Classes.

Référence

Classes

Une classe regroupe des données et les fonctions qui s'en servent. Une classe Led sait sur quelle broche est sa LED et sait l'allumer ; on crée ensuite autant de LED qu'on veut : ce sont des objets.

Tu en utilises déjà une : tout programme commence par class Main.

Une première classe

class Led {
    let broche                      // un champ : chaque Led a le sien

    constructor(b) {                // appelé à la création de l'objet
        this.broche = b
        gpio.mode(b, 1)
    }

    function allume(duree) {        // une méthode
        gpio.write(this.broche, 1)
        delay(duree)
        gpio.write(this.broche, 0)
    }
}

class Main {
    function main() {
        let led = new Led(2)        // crée un objet Led sur la broche 2
        while true {
            led.allume(300)         // appelle sa méthode
            delay(300)
        }
    }
}
ÉcritureSens
class Led { … }déclare la classe (au niveau global, nom avec une majuscule)
let brocheun champ : une variable que chaque objet possède (0 au départ, ou let broche = 2)
constructor(b) { … }le constructeur : exécuté à la création de l'objet
function allume(duree)une méthode : une fonction qui travaille sur l'objet
this.brochele champ broche de cet objet (dans la classe uniquement)
new Led(2)crée un objet ; les arguments vont au constructeur
led.allume(300)appelle la méthode allume de l'objet led

Chaque objet a ses propres champs : let bleue = new Led(2) et let rouge = new Led(4) pilotent deux LED différentes.

Les champs sont privés

Un champ ne se lit et ne s'écrit qu'avec this., dans la classe. De l'extérieur, on passe par une méthode. Dans une méthode, this.ajoute() appelle une autre méthode du même objet (sans this., ajoute() désignerait une fonction globale).

class Compteur {
    let valeur = 0

    function ajoute() {
        this.valeur += 1
    }

    function lire() {
        return this.valeur
    }
}

class Main {
    function main() {
        let c = new Compteur()
        c.ajoute()
        c.ajoute()
        print(c.lire())     // 2  (écrire c.valeur est refusé)
    }
}

L'héritage : extends

Une classe fille récupère les champs et les méthodes de sa classe parente, et peut en ajouter ou en remplacer.

class Animal {
    function cri() {
        return 0
    }
}

class Chat extends Animal {
    function cri() {        // remplace la méthode de Animal
        return 1
    }
}

class Main {
    function main() {
        let a = new Animal()
        let b = new Chat()
        print(a.cri())      // 0
        print(b.cri())      // 1
    }
}
  • Une méthode remplacée garde le même nombre de paramètres.
  • super.cri() appelle la version de la classe parente.
  • Si le constructeur parent prend des paramètres, celui de la classe fille doit l'appeler avec super(…). Une classe fille sans constructeur reprend celui de son parent.

Les classes abstraites : l'exemple motifs.chl

Une abstract class sert de modèle : on ne peut pas en créer d'objet, seulement des classes filles. Avec abstract function (sans corps), elle impose une méthode que chaque classe fille doit écrire. Dans motifs.chl, un Motif est une façon de faire clignoter la LED : il y en a plusieurs, mais tous savent jouer().

abstract class Motif {
    let led

    constructor(led) {
        this.led = led
    }

    abstract function jouer()       // chaque motif dira comment il joue

    function repeter(fois) {        // commune à tous les motifs
        let i = 0
        while i < fois {
            this.jouer()
            i += 1
        }
    }
}

class Clignote extends Motif {
    function jouer() {
        this.led.allume(300)
        delay(300)
    }
}

class Battement extends Motif {
    function jouer() {
        this.led.allume(80)
        delay(120)
        this.led.allume(80)
        delay(700)
    }
}

class Main {
    function main() {
        let led = new Led(2)        // la classe Led ci-dessus
        while true {
            let m = new Clignote(led)
            if random(1, 2) == 2 {
                m = new Battement(led)
            }
            m.repeter(2)
        }
    }
}
  1. Clignote et Battement n'ont pas de constructeur : ils reprennent celui de Motif, donc new Clignote(led) range led dans this.led.
  2. m.repeter(2) exécute la méthode de Motif, qui appelle this.jouer().
  3. this.jouer() choisit la version de la vraie classe de l'objet : repeter n'est écrite qu'une fois.

L'exemple complet ajoute un troisième motif, Morse. Essaie-le : chili push motifs.chl ; le terminal affiche le numéro du motif tiré à chaque tour.

Bon à savoir

  • Un objet est une valeur comme une autre : variable, champ, paramètre, valeur renvoyée.
  • 0 veut dire « pas d'objet » ; a == b est vrai si c'est le même objet.
  • La mémoire est libérée toute seule : un objet que plus rien ne désigne est récupéré automatiquement quand la place manque.
  • La carte garde jusqu'à 16 Ko d'objets (environ 2 000 objets à un champ en même temps). Les objets temporaires ne posent pas de problème ; en garder des milliers, si.
  • Il faut le firmware 0.2.0 ou plus récent : sinon, chili flash (ou le bandeau orange de Chili Lab).

print, delay, millis

Les extraits ci-dessous se placent dans function main() (ou une autre fonction).

  • print(v) affiche un entier ; la sortie apparaît pendant chili push ou avec chili monitor. Pas encore de texte.
  • delay(ms) : 1000 = 1 seconde. Une valeur nulle ou négative ne fait rien. Pendant un delay, la carte continue de répondre aux commandes.
  • millis() sert à mesurer une durée, ou à faire une action régulière sans bloquer le reste du programme :
let prochain = millis() + 1000
while true {
    if millis() - prochain >= 0 {
        print(millis())       // toutes les secondes
        prochain += 1000
    }
    delay(10)
}

Le compteur de millis() dépasse la limite des entiers 32 bits au bout d'environ 24 jours : compare toujours une différence (millis() - prochain >= 0), qui reste juste au passage de la limite.

Le hasard : random(min, max)

let de = random(1, 6)       // 1, 2, 3, 4, 5 ou 6
delay(random(200, 800))     // une pause imprévisible

Sur l'ESP32, le hasard vient du générateur matériel de la puce : vrai aléatoire, sans graine à choisir. Si max est plus petit que min, le programme s'arrête avec une erreur. L'exemple de.chl est un dé électronique : à chaque appui sur BOOT, la LED clignote de 1 à 6 fois.

Broches GPIO

Utilise le numéro GPIO de la broche (sérigraphié D2, GPIO2, IO2 ou 2). Appelle gpio.mode une fois au début pour chaque broche.

ModeNomUsage

1sortieLED, relais, buzzer…
2entrée + pull-upbouton entre la broche et GND : 1 relâché, 0 appuyé
3entrée + pull-downbouton entre la broche et 3,3 V : 0 relâché, 1 appuyé

Quand le programme s'arrête (stop, kill, nouveau push), ses sorties sont remises à 0 : LED et relais s'éteignent.

Exemples LED et bouton

LED externe

GPIO 4 → résistance 220 Ω → patte longue de la LED ; patte courte → GND.

let led = 4

class Main {
    function main() {
        gpio.mode(led, 1)       // sortie
        while true {
            gpio.write(led, 1)  // allumée
            delay(200)
            gpio.write(led, 0)  // éteinte
            delay(800)
        }
    }
}

Bouton BOOT → LED (bouton.chl)

let bouton = 0
let led = 2

class Main {
    function main() {
        gpio.mode(bouton, 2) // entrée avec pull-up
        gpio.mode(led, 1)    // sortie

        while true {
            if gpio.read(bouton) == 0 {
                gpio.write(led, 1)
            } else {
                gpio.write(led, 0)
            }
            delay(10)
        }
    }
}

Bouton externe : un fil sur GPIO 4, l'autre sur GND, et let bouton = 4. Pas de résistance nécessaire grâce au mode 2.

Compter les appuis (compteur.chl)

Pour détecter un appui, on compare avec l'état précédent :

let etat = gpio.read(bouton)
if avant == 1 && etat == 0 {   // passage relâché → appuyé
    appuis += 1
    print(appuis)
}
avant = etat
delay(20)   // évite de compter les rebonds du bouton

Avec chili run, les broches sont simulées : gpio.write affiche [gpio] broche 2 = 1 et gpio.read renvoie la dernière valeur écrite (0 au départ).

Référence

Les commandes

Toutes se tapent dans un terminal : chili <commande> [fichier] [cible]. chili help (ou chili seul) affiche la liste. À la souris : Chili Lab.

Sans fil

WiFi

Une fois la carte sur ton WiFi, tu lui envoies tes programmes sans câble ; elle peut être alimentée par n'importe quel chargeur.

L'ESP32 ne fonctionne qu'en WiFi 2,4 GHz : il ne voit pas les réseaux 5 GHz. Le PC et la carte doivent être sur le même réseau (évite les réseaux « invités »).

1. Connecter la carte (par USB, une fois)

chili wifi MaBox motdepasse
COM4 : identifiants enregistrés, connexion à « MaBox »… ok
  ip=192.168.1.42  host=chili-a1b2c3.local

Tu peux maintenant envoyer sans câble :
  chili push programme.chl 192.168.1.42

Espaces ou caractères spéciaux ($, &, ;…) : mets-les entre apostrophes, chili wifi 'Ma Box Maison' 'mon$ecret 2024'.

La carte retient le réseau et s'y reconnecte à chaque démarrage. Son nom chili-xxxxxx.local vient de son adresse MAC et ne change jamais.

2. Envoyer par WiFi

chili push blink.chl 192.168.1.42
chili push blink.chl chili-a1b2c3.local
chili monitor chili-a1b2c3.local
chili stop 192.168.1.42

Toutes les commandes de carte acceptent l'IP ou le nom. Seuls flash et wifi demandent le câble USB. L'IP peut changer après un redémarrage de la box ; le nom, non. Si Windows ne trouve pas le nom, utilise l'IP.

Retrouver l'adresse, changer de réseau

  • Par USB, chili check-port affiche WiFi : connecté, 192.168.1.42 (chili-a1b2c3.local).
  • Autre réseau : relance chili wifi AutreBox autremotdepasse. Couper : chili wifi off.
  • La carte écoute sur le port TCP 7070, une connexion WiFi à la fois.
Aide

Dépannage

Premier réflexe dans tous les cas : chili check-port. Elle dit ce qui est branché et quoi faire ensuite.

« Aucun port série détecté »

  1. Change de câble : cause n° 1. Prends un câble qui transfère des fichiers.
  2. Essaie un autre port USB du PC, sans hub.
  3. Installe le pilote de la puce USB (CH340 ou CP210x), débranche, rebranche.
  4. Contrôle dans le Gestionnaire de périphériques (clic droit sur Démarrer) → Ports (COM et LPT) : un port doit apparaître quand tu branches la carte.

« Aucune carte ESP32 reconnue »

Un port existe mais sa puce USB est inconnue. Force : chili check-port COM3, puis chili flash COM3.

Port occupé

  Port occupé : ferme les autres programmes qui l'utilisent (Arduino IDE, moniteur série…).

Un seul programme à la fois par port. Ferme Chili Lab (ou clique sur Déconnecter), Arduino IDE, PlatformIO, Thonny, PuTTY, ou l'autre terminal où tourne chili monitor (Ctrl+C).

« Aucune carte avec le firmware Chili n'a été trouvée en USB »

  • check-port dit Firmware Chili : absent : lance chili flash.
  • Port occupé (Chili Lab ouvert ?) : voir ci-dessus.
  • La carte ne répond plus : appuie sur EN et réessaie.

Mode programmation : BOOT / EN

Si la carte « ne passe pas en mode programmation automatiquement » :

  1. maintiens BOOT (parfois IO0 ou FLASH) ;
  2. appuie une fois sur EN (ou RST) ;
  3. relâche BOOT ;
  4. relance chili flash. Ensuite, appuie sur EN pour redémarrer normalement.

WiFi : « pas encore connecté »

  1. 5 GHz : l'ESP32 ne voit que le 2,4 GHz. Active-le dans ta box ou utilise son nom dédié.
  2. Vérifie nom et mot de passe (majuscules, espaces ; apostrophes autour s'il y a des espaces).
  3. Rapproche la carte de la box, puis chili check-port (connexion en cours… = patiente).
  4. connexion impossible avec un push par WiFi : l'IP a peut-être changé (check-port par USB), ou utilise l'IP plutôt que le nom .local.

Le programme s'arrête sur une erreur

[chili] erreur : division par zero (dans Main.main, pc 0008)

Le programme a fait une opération impossible ; la carte fonctionne toujours. Lis le message (liste des erreurs), teste sur le PC avec chili run, corrige, puis chili push.

Firmware à mettre à jour

  Firmware Chili : 0.1.3 (bytecode v1)
                   une autre version (0.2.0) est disponible : chili flash

COM4 : le firmware gère le bytecode v1, ce compilateur produit la v2.
Mets le firmware à jour avec : chili flash

COM4 : le firmware de la carte ne connaît pas « kill ». Mets-le à jour avec : chili flash

Après une mise à jour de Chili : chili flash par USB (ou le bandeau orange Mettre à jour de Chili Lab), puis renvoie ton programme. Obligatoire pour passer au firmware 0.2.0 : les programmes en class Main / function ne tournent pas sur un firmware plus ancien.

Autres cas

  • La LED ne clignote pas : check-port doit dire en cours d'exécution (sinon chili start). Toutes les cartes n'ont pas de LED sur GPIO 2 : branche une LED externe. Patte longue côté broche.
  • Rien dans monitor : le programme n'appelle pas print, ou il est en pause (chili start).
  • La carte redémarre en boucle : relance chili flash (avec BOOT / EN au besoin).
  • Repartir de zéro : chili erase efface le programme ; chili flash réinstalle le firmware.
À la souris

Chili Lab : l'application de bureau

Une application Windows pour tout faire sans terminal : état de la carte, envoi des programmes, console, firmware, WiFi. Elle contient déjà le compilateur et le firmware.

Installer et ouvrir

  1. Télécharge ChiliLabSetup-x.y.z.exe (par exemple ChiliLabSetup-0.1.0.exe) sur la page des versions.
  2. Double-clique dessus (SmartScreen : Informations complémentaires → Exécuter quand même). Pas besoin de droits administrateur.
  3. Coche Créer une icône sur le bureau si tu veux, puis Installer. Laisse Lancer Chili Lab coché et clique sur Terminer.

Ensuite : menu Démarrer → Chili Lab, ou double-clic sur l'icône du bureau. Une seule copie tourne à la fois : la relancer ouvre simplement une nouvelle fenêtre.

Un seul programme à la fois par port USB. Tant que Chili Lab est relié à la carte, chili push, chili monitor… dans un terminal disent que le port est occupé : clique sur Déconnecter ou ferme Chili Lab.

Fermer Chili Lab ne coupe pas la carte : le programme continue de tourner. Il faut Microsoft Edge (présent sur Windows 10/11) ou Google Chrome, avec lequel la fenêtre s'affiche.
